# Module report — M6 (Paramètres / settings), T-107

## What was built
- **T-107 — editable expense categories.** The fixed `EXPENSE_CATEGORIES` enum is gone. A new
  `expense_categories` table (key, label, sort order, archived flag) is seeded with the twelve former
  values so existing expenses keep their readable label, and is managed from
  **Paramètres → Facturation → Catégories de dépenses** (add, rename, archive).
- Endpoints: `GET /api/settings/expense-categories` (settings.read), `POST`, `PATCH /:key`,
  `DELETE /:key` (settings.write). A category that is already used by at least one expense cannot be
  deleted — only archived — and archived categories disappear from the expense form but stay valid on
  existing records.
- The expense endpoints validate the category against the table. An unknown **or archived** key is
  refused with `422 VALIDATION_ERROR`, `details.category = "unknown"`.
- Adding or renaming a category writes an activity entry (`activity.expense_category_added` /
  `activity.expense_category_updated`).

## Cross-cutting requirements
- **R-A** (nothing hard-coded): the list of categories is now data, and the dead constant was removed
  from `shared/domain.ts`. Labels come from the dictionary with a per-key fallback, so a category the
  owner adds himself is displayed with its own label in both languages.
- **R-B** (View): the management card lists every category read-only (label, key, archived flag) before
  any edit, and the expense detail screen already shows the category label.
- **R-C** (permissions): reading needs `settings.read` (administrators and managers), changing needs
  `settings.write` (administrators only); the check is server-side on every route, and a user without
  the permission sees the card in read-only mode.
