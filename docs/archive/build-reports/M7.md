## T-102a — CSV import backend (OQ-015) — DONE 2026-10-29
**What was built.** Templates per entity (clients, products) carrying the exact header row, an annotation row stating required/optional and accepted values, and one example row that passes validation. The importer accepts `;` or `,`, quoted cells and a UTF-8 BOM, so an exported file re-imports unchanged. Preview returns every row with its action (create/update by unique key), its issues and the detected delimiter; commit re-validates server-side and writes everything in one transaction.

**Rules.** GIVEN a file with a duplicate unique key WHEN previewed THEN both rows are flagged and the commit is refused until the user either fixes them or explicitly asks to exclude invalid rows. GIVEN a missing required column WHEN previewed THEN the column is named. GIVEN an optional column absent THEN its default applies (country = Polynésie française, payment terms = 30 days, currency = company currency).

**Checks run.** 77/77 unit tests (11 new), typecheck and build clean; live walk as recorded in the changelog.

**Deviations.** Only required columns must be present (the sheet's wording implied every template column); this keeps hand-made files usable and is documented in the sheet.

**Could not verify.** The wizard screen does not exist yet (T-102b); everything above was exercised through the API.

## T-102b — Import wizard screen — DONE 2026-10-29
`/importer` walks the five steps of the sheet: template download, file or paste, row-by-row preview with the detected delimiter and the create/update action, an explicit choice before skipping rows in error, then a result report. The screen is reachable from Administration and only for users who may write the chosen data type.
Verified: typecheck, build and 77 tests. Not verified: the visual rendering (no browser in this environment); the endpoints it calls were verified live in T-102a.

## T-102c — Invoices import — DONE 2026-10-29
One row per line item, grouped by invoice number. The client is matched by e-mail, client number or exact name; rows of one document must agree on client, date and due date; an invoice number already present is refused rather than duplicated; imported documents are created as drafts with totals from the shared tax engine. The invoices export was reshaped to the same layout, so invoices round-trip like clients and products.
Verified: 84/84 tests, typecheck and build clean, live walk (2 rows → 1 draft of 80 040, duplicate refused with 409).
