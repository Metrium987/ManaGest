# 04 — Functional entities comparison (business objects, not storage)

Replaces the earlier storage-level comparison (now withdrawn per audit course-correction: this audit compares what users can see, enter and obtain, not database engines). Verdict vocabulary per section 9 of the mission. `[OBSERVED]` = read in code; `[EXECUTED]` = run in ManaGest; `[OBSERVED-UI]` = Playwright specs (shipped-UI evidence).

## Side-by-side: business objects a user works with

| **Supplier/Vendor** | Vendor + vendor contacts portal | Vendor simple record (no contacts) | `PARTIAL` |

## Where the baseline is user-visible but the platform can't deliver today

Anything requiring (a) **outbound email**, (b) **scheduled triggers** (recurring generation, reminders, quote expiry), (c) **external gateways**, (d) **file storage for uploads**, or (e) **client-facing portal hosting** is not rejected as "missing implementation" but recorded per audit §9 as `PLATFORM-DEPENDENT` (state the capability) or via `EQUIVALENT-BY-PLATFORM` where the same user outcome is achieved by other platform means. Current ManaGest runs natively without these; the audit logs which behaviour each capability would unlock — see `05-parity-matrix.md` aggregated rows.
